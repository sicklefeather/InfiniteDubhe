## 1. 概述

本文档定义**无限天枢引擎（Infinite Dubhe Engine）**的**架构与核心类设计**，是需求文档（`需求文档.md`）的实现落地方案。粒度到"接口签名 + 模块职责 + 数据流"，不涉及具体实现代码。

### 1.1 已确定的决策（回顾）
| 决策 | 结论 |
|------|------|
| 图形/窗口基础 | Silk.NET（自研，不基于 MonoGame） |
| 实体模型 | GameObject-Component |
| 序列化 | System.Text.Json + `ISerializer` 门面（通用 JSON；场景序列化由 `SceneSerializer` 专责，见 §4.7） |
| 平台 | 本期仅 Windows；Android/Web 仅预留 |
| 脚本热重载 | 暂不实现，只做资源热重载 |
| 3D | 不预先设计抽象，按需扩展（§13 Q6） |

### 1.2 设计原则
1. **克制抽象**：接口只为当前真实用例服务，不为臆想的未来设计（见需求 Q6）。
2. **依赖单向**：上层依赖下层，下层不反向依赖上层。
3. **平台隔离**：核心逻辑零平台依赖，平台能力全走 PAL 接口。
4. **可无头测试**：逻辑与渲染分离，核心子系统可在无图形环境下单测。

### 3.1 程序集职责与依赖方向

```
Core（无依赖）
  ▲
  ├── Platform（依赖 Core）
  ├── Scene（依赖 Core）
  │
Rendering（依赖 Core + Platform）
Input（依赖 Core + Platform）
Resources（依赖 Core + Platform + Scene + Rendering）
Physics（依赖 Scene，M2）
Audio（依赖 Core + Platform，M2）
UI（依赖 Rendering + Input + Scene，M2）
Engine（依赖 Core + Platform + Rendering + Scene + Input + Resources + Audio）   # GameHost 主循环
  ▲
Host/Game 程序集（依赖以上全部）
```

> `Core` 除数学/容器/时间/日志/事件外，还承载**跨层共享的契约类型**：`ISerializer` 接口（序列化门面）、渲染契约（`Color`/`Rectangle`/`SpriteEffects`/`ITexture`/`IRenderable`/`SpriteDrawCommand`）以及输入契约（`Key`/`MouseButton` 枚举）。这些类型"无依赖、被所有层共享"，若不放 `Core`，就会迫使 `Scene` 与 `Rendering`、或 `Platform` 与 `Input` 互相引用（见 §4.4/§4.5）。

**规则**：
- 禁止反向依赖（如 `Scene` 引用 `Rendering`）。
- 组件逻辑通过**事件/接口**与渲染器解耦，而不是直接持有渲染器引用。
- `Resources` 依赖 `Scene`/`Rendering` 属**单向**：场景、纹理都是"资源类型"，其加载与序列化在 `Resources` 落地（§4.7），`Scene`/`Rendering` 不反向依赖 `Resources`。

## 4. 核心类设计

### 4.1 应用与主循环（`InfiniteDubhe.Core` + `InfiniteDubhe.Engine`）

用户入口：继承 `Game`，重写生命周期方法，在 `Main` 中调用 `Run`。

> **分层说明**：`Game` 抽象基类（仅生命周期钩子 + `Config`）位于 `Core`（无依赖）；主循环在 **`Engine.GameHost`**（依赖 Core + Platform + Rendering）实现，负责装配窗口/渲染器/时钟并驱动循环。`Game` 的 `On*` 内部入口经 `InternalsVisibleTo("InfiniteDubhe.Engine")` 由 `GameHost` 调用。这样 `Core` 保持零平台依赖，主循环又能访问 Platform/Rendering。

```csharp
// InfiniteDubhe.Core
public abstract class Game
{
    public GameConfig Config { get; }          // 分辨率、标题、是否全屏等
    public IServiceProvider? Services { get; } // 子系统访问入口（由 GameHost 注入）
    protected T? GetService<T>() where T : class; // 解析子系统（SceneManager/ResourceManager/Renderer）

    protected virtual void Initialize();       // 创建资源、注册系统
    protected virtual void LoadContent();      // 加载资源
    protected virtual void Update(float dt);   // 每帧逻辑（可变 dt）
    protected virtual void FixedUpdate(float dt); // 固定步长逻辑（可选）
    protected virtual void Render();           // 提交渲染
    protected virtual void UnloadContent();    // 释放资源
    protected virtual void Shutdown();         // 退出清理

    // 内部 On* 入口（internal）供 Engine.GameHost 调用，用户不直接使用。
}
```

**主循环（引擎内部，固定步长 + 可变渲染）**：

```csharp
// 伪代码
while (running)
{
    frameDt = clock.Tick();              // 本次帧间隔（做上限钳制，防窗口拖动导致 dt 巨大）
    accumulator += frameDt;

    while (accumulator >= fixedDt)       // fixedDt 默认 1/60
    {
        FixedUpdate(fixedDt);
        accumulator -= fixedDt;
    }

    Update(frameDt);
    Render();
    present();                           // 交换缓冲 / VSync
}
```

**时间 API**（`Core.Time`）：
```csharp
public static class Time
{
    public static float DeltaTime;         // 当前帧 dt（未缩放）
    public static float FixedDeltaTime;    // 固定步长
    public static float TimeScale;         // 时间缩放（暂停=0）
    public static float TotalTime;         // 累计运行时间
    public static float ScaledDeltaTime { get; }  // DeltaTime * TimeScale
}
```

> 说明：MVP 阶段 `Time` 用静态类即可，简单够用；若后续需要多时钟（如 UI 单独时间轴）再升级为实例。主循环每帧把 `IClock.Tick()` 的结果写入 `Time.DeltaTime`/`TotalTime`，`FixedDeltaTime` 取配置的固定步长。

### 4.2 游戏对象与组件（`InfiniteDubhe.Scene`）

```csharp
public sealed class GameObject
{
    public string Name { get; set; }
    public Transform Transform { get; }        // 必有
    public Scene Scene { get; }                // 所属场景
    public Guid Id { get; }                    // 创建时生成，全局唯一，用于序列化引用重连（§4.7）
    public bool Active { get; set; }           // 激活开关（影响子节点）

    public T AddComponent<T>() where T : Component, new();
    public T GetComponent<T>() where T : Component;
    public bool TryGetComponent<T>(out T component);
    public IEnumerable<Component> GetComponents();

    public GameObject CreateChild(string name); // 建立父子层级
    public void Destroy();                      // 延迟到本帧末销毁（并从所属场景移除）
}

public abstract class Component
{
    public GameObject GameObject { get; }
    public Transform Transform { get; }         // 快捷访问
    public bool Enabled { get; set; }           // 组件开关（控制 Update 是否调用）

    protected virtual void Awake();
    protected virtual void OnEnable();
    protected virtual void Start();             // 首帧 Update 前调用一次
    protected virtual void Update();
    protected virtual void FixedUpdate();        // 固定步长回调（物理等），与 Update 分离
    protected virtual void OnDisable();
    protected virtual void OnDestroy();
}
```

**生命周期约定**（参考 Unity，MVP 精简版）：
1. `AddComponent` → 立即 `Awake`（对象已就位）
2. 场景激活时 → `OnEnable`
3. 首帧 → `Start`
4. 每帧 → `Update`（仅 `Enabled && Active` 时）
5. 固定步长每步 → `FixedUpdate`（仅 `Enabled && Active` 时，主循环累积调用）
6. 禁用/销毁 → `OnDisable` → `OnDestroy`

> 组件回调不传 `dt` 参数，统一读取静态 `Time.DeltaTime`/`Time.FixedDeltaTime`（与 `Game` 层的 `Update(float dt)` 等价，由主循环每帧写入，见 §4.1）。

```csharp
public sealed class Transform
{
    public Vector2 Position { get; set; }
    public float RotationDeg { get; set; }   // 角度，2D 只需单轴旋转
    public Vector2 Scale { get; set; }       // 默认 (1,1)

    public Transform Parent { get; }
    public IReadOnlyList<Transform> Children { get; }   // 子节点（只读视图）
    public void SetParent(Transform? parent);           // 重新挂载，传 null 移到根级

    public Vector2 WorldPosition { get; }    // 累加父级变换
    public Matrix3x2 LocalToWorld { get; }   // 2D 用 3x2 矩阵，避免 4x4 浪费
}
```

> 2D 阶段用 `System.Numerics.Matrix3x2` 表达变换，足够且轻量；引入 3D 时再扩展（不预先设计）。

### 4.3 场景管理（`InfiniteDubhe.Scene`）

```csharp
public sealed class Scene
{
    public string Name { get; set; }        // 可写；不入 JSON：加载时以文件名命名，保存后同步为文件名
    public IReadOnlyList<GameObject> RootObjects { get; }

    public GameObject CreateObject(string name);   // 创建根级对象
}

public sealed class SceneManager
{
    public Scene? Global { get; }           // 常驻全局场景（跨关卡存活的对象，如 UI/音频管理器）
    public Scene? Current { get; }          // 当前关卡场景
    public void SetGlobal(Scene? scene);    // 设置全局场景（传 null 清除）
    public void Load(Scene? scene);         // 切换关卡场景（传 null 清除）
}
```

- **双场景模型**：全局场景与关卡场景同时步进（`Update`/`FixedUpdate`）与渲染，全局对象跨关卡存活（供编辑器「全局场景」与运行时常驻对象使用）。
- `SceneManager` 只负责**场景生命周期**（卸载旧、激活新），**不做文件 I/O 与反序列化**。
- 从**文件加载场景**由 `Resources` 层的 `SceneLoader` 负责（场景是资源的一种）：`SceneLoader.LoadScene(path)` → 读文件 → `SceneSerializer` 反序列化（场景名以文件名命名）→ 引用重连（GUID→对象、GUID/路径→资源句柄）→ 返回 `Scene`，再由 `SceneManager.Load` 切换（见 §4.7）。
- 场景切换流程：`UnloadContent` 级清理 → 卸载旧场景所有对象 → 激活新场景。

### 4.4 平台抽象层 PAL（`InfiniteDubhe.Platform`）

### 4.5 渲染（`InfiniteDubhe.Rendering`）

MVP 只做 2D，接口**不写死 2D 专用假设但也不预设计 3D**。

**渲染解耦**：`Scene` 不能反向依赖 `Rendering`，但 `SpriteRenderer`（Scene 层组件）又必须描述"画什么、画在哪"。解决方式是把**渲染契约类型下沉到 `Core`**（无依赖、被所有层共享，见 §3.1）：

```csharp
// Core —— 渲染契约（Scene 与 Rendering 共享）
public struct Color { /* RGBA */ }
public struct Rectangle { /* 整数矩形，源矩形用 */ }
public enum SpriteEffects { None, FlipHorizontally, FlipVertically }

public interface ITexture          // 纹理句柄；Rendering.Texture2D 实现它
{
    int Width { get; }
    int Height { get; }
}

public interface IRenderable        // 可渲染对象；Scene.SpriteRenderer 实现它
{
    void Submit(ICollection<SpriteDrawCommand> commands);  // 收集本对象的绘制指令（集合由引擎池化）
}

public struct SpriteDrawCommand      // 单条精灵绘制指令（POD，供批处理）
{
    public ITexture Texture;
    public Rectangle SourceRect;
    public Vector2 Position;
    public float Rotation;           // 弧度
    public Vector2 Origin;
    public Vector2 Scale;
    public Color Color;
    public SpriteEffects Effects;
    public int Layer;                // 排序层
    public float LayerDepth;         // 同层内深度
}

> **角度单位约定**：用户面 API（`Transform.RotationDeg`、`Camera.RotationDeg`）用**度**；内部热路径（`SpriteDrawCommand.Rotation`、矩阵）用**弧度**。度→弧度在 `SpriteRenderer.Submit` 收集绘制指令时**统一换算一次**，避免散落各处。
```

**渲染实现（`Rendering`，依赖 `Core` + `Platform`）**：

```csharp
public sealed class Renderer : IDisposable          // 渲染入口，唯一接触具体后端（D3D11）
{
    public Camera Camera { get; }
    public Color ClearColor { get; set; }            // 默认 CornflowerBlue
    public void Initialize();                        // 获取后端句柄并创建 SpriteBatch 等 GPU 资源
    public Texture2D CreateTexture(int width, int height, ReadOnlySpan<byte> rgba); // 程序化纹理 / 上传
    public RenderTarget2D CreateRenderTarget(int width, int height);  // 创建离屏渲染目标（编辑器视口等用）
    public void Clear(Color color);
    public void Draw(IReadOnlyList<IRenderable> renderables); // 收集指令 → 批处理 → 绘制到后备缓冲（后接 Debug pass）
    public void Draw(IReadOnlyList<IRenderable> renderables, RenderTarget2D target); // 渲染到离屏目标（视口）
    public void Present();
}

public sealed class Texture2D : ITexture, IDisposable
{
    public int Width { get; }
    public int Height { get; }
}

public sealed class RenderTarget2D : ITexture, IDisposable   // 离屏渲染目标：可渲染进它，也可作普通纹理采样
{
    public int Width { get; }
    public int Height { get; }
}

public sealed class SpriteBatch : ICollection<SpriteDrawCommand>, IDisposable
{
    public void Begin(Camera camera);            // 开始批处理，绑定相机
    public void Draw(ITexture tex, Vector2 position, Color color);
    public void Draw(in SpriteDrawCommand command);
    public void End();                          // 按 (Layer, LayerDepth, 纹理) 排序后合并 Draw Call
}

public sealed class Camera
{
    public Vector2 Position { get; set; }
    public float Zoom { get; set; }             // 默认 1
    public float RotationDeg { get; set; }
    public int ViewportWidth { get; set; }
    public int ViewportHeight { get; set; }
    public Matrix3x2 ViewMatrix { get; }        // 世界 → 裁剪空间（正交投影 + 相机变换）
}
```

> `RenderTarget2D` 为可绑定 RTV 的离屏目标：`Renderer.Draw(renderables, target)` 先把 RTV/视口绑定到目标，再走与后备缓冲同一套批处理绘制，之后可作普通纹理（`ITexture`）采样——编辑器视口即「场景渲染进 RTT → 以纹理呈现」（编辑器设计文档 G-01，纯增量、不改后备缓冲路径行为）。视口尺寸变化时由调用方**重建**目标（离屏目标不支持原地 Resize）。

**渲染数据流**：
```
SpriteRenderer 组件 → Submit 收集 Draw 指令 → SpriteBatch 按(纹理,混合状态)分组 → 合并为 Draw Call → 提交 GPU
```

- `SpriteRenderer` 挂在 `Scene` 的 GameObject 上，实现 `IRenderable`（Core），只持有 `ITexture` 句柄，**不持有也不认识 `Rendering.Texture2D` 的 GPU 实现**——反向依赖由此消除。
- 渲染器（`Rendering`）由 Host/Game 层传入 `IRenderable` 集合（经 `Scene` 收集），按图层/排序键分组后调用 `SpriteBatch` 提交。
- 混合状态/排序键/图层见需求 §7.1（M1 实现）。

### 4.6 输入（`InfiniteDubhe.Input`）

- 底层实现由 PAL 的 `IInputSource` 提供（Windows 用 Silk.NET 轮询窗口事件）。
- 引擎层封装为 `Input` 静态门面 + **动作映射（Action Mapping）**（M1）：

```csharp
public static class Input
```

### 4.7 资源管理与序列化（`InfiniteDubhe.Resources`）

```csharp
public interface IResourceLoader<T> where T : class
{
    T Load(string path);
}

> `IResourceLoader<T>` 由各类资源实现，并按类型注册到 `ResourceManager`；`ResourceManager.Load<T>` 据此分派到对应加载器。二者是"注册表 + 加载器"的关系，不是两套并列 API。

public sealed class ResourceManager
{
    public void RegisterLoader<T>(IResourceLoader<T> loader);  // 按资源类型注册加载器
    public T Load<T>(string path) where T : class;   // 同步，带引用计数，同路径复用
    public Task<T> LoadAsync<T>(string path);        // 异步（M1）
    public void Unload(string path);                 // 释放引用，归零才真正释放
    public string? GetPath(object resource);         // 反向查询已缓存资源的加载路径（供序列化把句柄还原为路径）
    public void Reload<T>(string path);              // 热重载单个资源（重新加载并替换缓存实例，触发 ResourceChanged）
    public void ReloadAll<T>();                      // 热重载该类型全部已缓存资源
    public event Action<string> ResourceChanged;     // 资源变更/热重载触发点（M3）
}
```

**序列化门面**（对用户透明，底层 STJ）：

```csharp
public interface ISerializer
{
    string Serialize<T>(T value);
    T Deserialize<T>(string json);
    object? Deserialize(string json, Type type);      // 多态场景用
}
```

**场景/资源序列化的特殊处理**（`SceneSerializer` + 扁平 DTO，见 `API文档.md` §10.3）：
- **场景格式**：扁平 `SceneFile` DTO（`Version` + 对象扁平列表 + GUID 父子引用）；**场景名不入 JSON**——加载时以文件名命名（`SceneLoader.NameFromPath` 剥 `.json`/`.scene` 后缀），重命名场景 = 重命名文件；`Scene.Name` 可写，供编辑器保存后同步。
- **对象引用**：实体间引用存 `GameObject.Id`（GUID），反序列化时重连。
- **多态**：组件类型记 `AssemblyQualifiedName`（`ComponentData.TypeName`），经反射重建并按公开可写属性赋值，统一覆盖内置与自定义组件——不使用 STJ 的 `$type` 多态。
- **资源引用**：存 **GUID + 相对路径**（`AssetReference`，经 `IAssetGuidResolver` 以 GUID 为主、路径回退，改名/移动后稳定重连），反序列化时经 `ResourceManager` 解析为句柄。
- **引用重连时机**：在**反序列化阶段**由 `SceneSerializer` 完成（先建全部对象 → 按 `ParentId` 重挂父子 → 建组件/重连资源）；反序列化后得到的 `Scene` 即为"就绪"状态，可直接交给 `SceneManager.Load`。
- **UI 树 / 子树**：`Canvas` 根元素树经 `UiElementData` 反射式序列化（`IsAutoGenerated` 子元素跳过）；`SerializeSubtree/DeserializeSubtree` 支持单对象子树往返（编辑器删除撤销快照、预制体）。

**场景加载器**（`Resources` 层）：场景是资源的一种，故由 `Resources` 提供 `SceneLoader` 封装"读文件 → 反序列化 → 引用重连"全过程（见 §4.3）。

```csharp
public sealed class SceneLoader
{
    public SceneLoader(IFileSystem fileSystem, SceneSerializer serializer);
    public Scene LoadScene(string path, string? name = null);  // 读文件 + SceneSerializer 反序列化 + 引用重连；name 缺省取 NameFromPath(path)，固定场景可显式指定
    public static string NameFromPath(string path);            // 剥 .json / .scene 后缀得到场景名（空名回退 "Scene"）
    public void SaveScene(Scene scene, string path);
    public string Serialize(Scene scene);                      // 序列化不落盘（供编辑器脏检测比对）
    public bool Exists(string path);
}
```

> `ISerializer` 接口定义在 **`Core`**、STJ 实现 `JsonSerializer` 在 `Resources`（通用 JSON 门面，配置/存档用）。**场景序列化由 `Resources` 的 `SceneSerializer` 专责**：为处理 GUID 重连、反射重建与 UI 树，直接使用 System.Text.Json + DTO 层 + 自定义转换器，不经 `ISerializer` 门面。

### 4.10 协程与延时调用（`InfiniteDubhe.Core`）

### 4.13 物理（`InfiniteDubhe.Physics`）

封装 Aether.Physics2D（Box2D 的 C# 移植）。用户面用 `System.Numerics` + 像素单位；内部经 `AetherMath` 换算（**1 物理单位 = 100 像素**），因为 Box2D 的调参常量（`MaxTranslation` 等）为编译期常量、以"米"级为单位。屏幕 +y 向下，故旋转角度取反以保持屏幕旋转方向一致。

**组件模型**：
- `PhysicsWorld2D : Component` —— 挂到场景，`Awake/OnEnable` 登记为 `Physics2D.ActiveWorld`，`FixedUpdate` 步进世界并同步刚体。
- `Rigidbody2D : Component` —— `OnEnable` 注册到活动世界，读 `Transform` 创建 Body；**动态**刚体每步 Body→Transform，**静态/运动学**刚体每步 Transform→Body。
- `Collider2D : Component`（抽象）→ `BoxCollider2D` / `CircleCollider2D`，挂在含 `Rigidbody2D` 的对象上，由刚体据此创建 Fixture。

```csharp
public sealed class PhysicsWorld2D : Component
```

### 4.16 UI（`InfiniteDubhe.UI`）

UI 元素**不是组件**，由 `Canvas`（`Component` + `IRenderable`）持有并驱动。`Canvas` 挂在 GameObject 上，`Initialize(Renderer)` 生成白色纹理与内置位图字体图集（**`GameHost` 每帧幂等地为未初始化的 Canvas 调用 `Initialize`**，运行期新建/反序列化的 Canvas 无需手动调用）。布局模型：锚点(父空间 0–1) + 枢轴(自身 0–1) + 像素偏移 + 尺寸；流式布局用 `Layout` 方向 + `Spacing`/`Padding`。渲染走 `IRenderable.Submit`，用高层 `SortingLayer`（默认 1000）置顶，元素按树序递增 `LayerDepth` 保持 z 序。交互在 `Canvas.Update` 里命中测试（逆序、子元素优先）并派发悬停/点击。

## 5. 一帧的数据流

```
[主循环]
  clock.Tick()
    ├── FixedUpdate（固定步长累积）
    │     ├── 组件 FixedUpdate → 物理步进（PhysicsWorld2D）
    │     └── 协程 FixedUpdate（释放 WaitForFixedUpdate）
    ├── Update(dt)
    │     ├── 遍历激活组件 Update → 输入 → 逻辑 → 更新 Transform
    │     └── 推进 Coroutines / Tween / Audio
    ├── Render()
    │     ├── 收集 IRenderable（SpriteRenderer / Canvas 等）
    │     ├── SpriteBatch 分组排序 → 提交 GPU 绘制
    │     ├── Debug 图元 flush（精灵之上，独立 pass）
    │     └── SwapBuffers / VSync
    └── 帧末清理（延迟 Destroy、事件派发）
```

|------|------|------|
| 类/结构/枚举 | PascalCase | `SpriteBatch`, `GameState` |
| 接口 | `I` 前缀 + PascalCase | `IWindow`, `ISerializer` |
| 公共方法/属性 | PascalCase | `AddComponent`, `WorldPosition` |
| 私有字段 | `_camelCase` | `_accumulator`, `_texture` |
| 局部变量/参数 | camelCase | `frameDt`, `deltaTime` |
| 常量 | PascalCase | `FixedDeltaTime` |
| 布尔属性 | `Is/Has/Can` 前缀 | `IsClosing`, `HasComponent` |

### 7.2 命名空间与目录
- 命名空间根 = 程序集名（`InfiniteDubhe.Scene` 等）。
- 文件夹结构与命名空间一一对应。

### 7.3 内存与性能约定（关键路径）
- `Update`/`Render` 热路径**禁止**：LINQ、闭包分配、`foreach` 装箱、字符串拼接（用 `StringBuilder`/缓存）。
- 常用结构尽量用 `struct`（如 `Color`、`Rectangle`），减少 GC 压力。
- 每帧临时对象用对象池或复用缓冲。
- 集合优先 `List<T>`，避免频繁 `Dictionary` 增删。

### 7.4 错误处理
- **公共 API 参数校验**：`ArgumentNullException` / `ArgumentOutOfRangeException`。
- **引擎内部**：`Debug.Assert` + 返回错误码，不抛异常进热路径。
- **日志分级**：Info（正常流程）、Warn（可恢复异常）、Error（不可恢复）。

### 7.5 注释与文档
- 公共 API 一律 XML 文档注释（`/// <summary>`），说明用途与约束。
- 复杂算法写"为什么"，不写"做了什么"。

| 层 | 测试方式 | 覆盖 |
